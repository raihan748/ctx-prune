## 1. Overview & Problem Statement

When feeding codebases into Large Language Models (OpenAI GPT-4, Anthropic Claude 3.5, Google Gemini 1.5), developers and agents routinely waste **40% to 75%** of their prompt context window on:
1. **Redundant Comments & Docstrings**: Module comments, trailing inline explanations, license headers, and autogenerated notices.
2. **Whitespace Bloat**: Trailing indentation spaces and sequences of multiple blank lines.
3. **Low-Priority Artifacts**: Test files, fixtures, mock data, and auxiliary configuration files consuming the budget before core logic can be ingested.
4. **Context Window Overflow**: Truncating critical entry points or core domain services because files were ingested in arbitrary filesystem order.

`ctx-prune` is a high-performance, pure-Rust CLI tool and library that extracts, prunes, minifies, and packs codebases under an **exact token budget constraint** using language-aware FSM comment stripping, genuine Byte Pair Encoding (BPE) estimation, signature-only AST skeleton extraction, and priority-tier knapsack packing.

## 3. Core Capabilities

### 3.1 Language-Aware Comment & Whitespace Stripper FSM (`src/stripper.rs`)
- Single-pass **Deterministic Finite Automaton (DFA)**.
- **C-Family (C, C++, Rust, Go, Java, JS, TS)**: Removes `//` line comments and `/* ... */` block comments. Preserves string literals containing comment syntax (e.g. `"https://domain.com//test/*"`).
- **Rust Nested Comments & Raw Strings**: Tracks comment nesting depth `/* /* nested */ */` and recognizes raw string literals `r#"..."#` without false-positive comment parsing.
- **Python Docstring Classifier**: Distinguishes standalone docstrings (`"""..."""` or `'''...'''` at module, class, or function scope) from multiline string variables.
- **Whitespace Collapser**: Trims trailing whitespace and collapses runs of 3+ blank lines to a single blank line.

### 3.2 Pure-Rust cl100k_base BPE Tokenizer (`src/bpe.rs`)
- Zero external C/Python dependencies.
- Splits text using the Unicode-aware regex specification:
  `(?i:'s|'t|'re|'ve|'m|'ll|'d)|[^\r\n\p{L}\p{N}]?\p{L}+|\p{N}{1,3}| ?[^\s\p{L}\p{N}]+[\r\n]*|\s*[\r\n]+|\s+`
- Performs iterative pair merge lookups against the cl100k rank vocabulary to calculate exact token counts matching OpenAI GPT-4 / Claude reference oracles.

### 3.3 AST Skeleton Fallback Engine (`src/ast_skeleton.rs`)
- When a critical Tier 1 or Tier 2 file cannot fit into the remaining token budget in full, `ctx-prune` automatically compresses it to an **interface skeleton**:
  - In **Rust**: Replaces function bodies `{ ... }` with `;`, preserving `pub struct`, `pub enum`, `trait`, and type signatures.
  - In **Python**: Replaces function bodies with `...` or `pass`, preserving class and method definitions.
  - In **TypeScript / Go / C**: Retains prototypes and interfaces while omitting internal implementation details.

### 3.4 Priority Knapsack Packer (`src/packer.rs`)
Files are categorized into 4 hierarchical priority tiers:
1. **Tier 1 (Entry Points)**: `main.rs`, `lib.rs`, `index.ts`, `app.py`, `main.go`.
2. **Tier 2 (Core Logic)**: Domain models, services, business logic, route handlers.
3. **Tier 3 (Utilities & Config)**: Helpers, formatters, configurations.
4. **Tier 4 (Tests & Fixtures)**: `tests/`, `*_test.rs`, `fixtures/`, specs.

Files are sorted by `(Priority ASC, TokenCount ASC)` and greedily packed into the prompt until `--max-tokens` is reached.

## 5. CLI Installation & Usage Guide

### 5.1 Building from Source
Ensure Rust 1.75+ is installed:
```bash
cargo build --release
```
The compiled binary is located at `target/release/ctx-prune.exe` (or `target/release/ctx-prune` on Linux/macOS).

### 5.2 Basic Usage

#### 1. Slicing a repository under an 8,000 token budget
```bash
ctx-prune . --max-tokens 8000
```

#### 2. Exporting to a Markdown prompt file
```bash
ctx-prune ./src --max-tokens 4000 --format markdown -o prompt_context.md
```

#### 3. Generating JSON output for programmatic LLM tool calls
```bash
ctx-prune ./src --max-tokens 12000 --format json -o context.json
```

#### 4. Extracting interface skeletons only (maximum compression)
```bash
ctx-prune ./src --skeleton --max-tokens 2000
```

#### 5. Filtering specific file extensions
```bash
ctx-prune . --ext rs,py,ts --max-tokens 6000
```

### 5.3 CLI Flags & Options

| Option / Flag | Short | Default | Description |
|---|---|---|---|
| `<PATHS>...` | | `.` | Files or directories to recursively scan and pack |
| `--max-tokens <NUM>` | `-m` | `8000` | Strict token budget constraint |
| `--format <FORMAT>` | `-f` | `markdown` | Output rendering format (`markdown`, `json`, `raw`) |
| `--output <FILE>` | `-o` | `stdout` | Destination file for rendered prompt context |
| `--skeleton` | `-s` | `false` | Force signature-only AST skeleton extraction for all files |
| `--fallback-skeleton` | | `true` | Automatically convert Tier 1/2 files to skeletons if they exceed budget |
| `--no-strip-comments` | | `false` | Disable comment stripping (preserve comments verbatim) |
| `--keep-docstrings` | | `false` | Preserve docstrings while stripping other comments |
| `--no-collapse-whitespace`| | `false` | Disable whitespace collapsing |
| `--ext <EXTENSIONS>` | `-e` | `all` | Comma-separated extension filter (e.g. `rs,py,go`) |
| `--summary` | | `true` | Print ANSI color summary table to stderr |
